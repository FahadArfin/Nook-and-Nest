# Floor plan studio

Uploading a PDF, PNG, JPEG or WebP now starts automatic analysis. PDF.js renders only the selected page locally; the rendered image is sent through the authenticated site server to OpenAI. The studio receives room areas, printed dimension evidence, closets, balconies, doors/windows and service fixtures. Document writing is treated as untrusted data, never instructions. The server uses store:false and does not save the scan or response in the project database. References are not included in exports, cloud projects or shared plans.

Printed dimensions establish millimetres per pixel; missing or inconsistent measurements cause a readable failure instead of invented scale. Rooms, measurements, names and fixtures are editable before confirmation. Recognition can be canceled, preserves the existing draft on failure, and cannot overwrite newer home changes. Changing the PDF page or rotation reanalyzes that page. Blank drawings and the existing manual correction tools remain available.

The current floor engine represents orthogonal rectangular regions. L-shaped spaces use adjacent regions internally, but each physical room has one group, one label and one editable selection. The room counter excludes closets and circulation, which have a separate list. Related regions move, resize, rename and auto-furnish together; their boundaries are unioned before generating inside walls. Group metadata and generated-wall ownership survive confirmation, export, undo and reopening. Skewed, curved and diagonal boundaries remain approximations and are explicitly called out for review. An opening that would snap more than 500 mm away is left out and reported rather than moved to a different room. Small opening clearance corrections are also reported. Uncertain service symbols and labels appear in the review notes. This is an initial furnishing layout, not a measured architectural survey.

Confirm the reviewed plan to replace the active floor in one undo step. Loose furniture is excluded. Recognized kitchen/bath/laundry fixtures and accepted openings become independently editable catalog placements. Other floors remain; inbound stair connections are removed with the replaced layout. A separate Auto furnish button previews library furniture, with explicit apply/discard and one-step undo. Local autosave and explicit online saving retain their existing behavior.

## Server configuration

Sites runtime secret OPENAI_API_KEY is required. Luna (gpt-5.6-luna) is the default. The old FLOOR_PLAN_MODEL override is ignored. Astra is allowed only through explicit model selection plus per-request premium confirmation; there are no automatic retries or model upgrades. Credentials never enter the client build. Signed-in users may run up to 10 analyses per UTC day, and the site permits at most 100 total per UTC day; failed provider attempts count. D1 migration 0001_recognition_usage stores only daily counters. Request bodies are bounded to 9 MB and provider output is independently validated. Anonymous users can still use the manual editor; automatic analysis requires ChatGPT sign-in.

For loopback-only development, set NOOK_OPENAI_KEY_FILE to an external local text file containing the key before starting Vite. The optional dev adapter reads it server-side, uses an in-memory daily counter and supplies a development identity. Production uses trusted Sites identity and atomic D1 counters. Do not commit key files, scans or real recognition outputs.

Tests cover printed scale, inconsistent/missing dimensions, unsafe geometry and catalog IDs, authentication/origin rejection, usage limits, provider refusals/incomplete output, cancellation, retained drafts, editable detected rooms, 3D confirmation and undo. The private example PDF is exercised separately against the actual vision API and is not a repository fixture.

Completed, schema-validated detections are cached on the browser for 30 days, up to 10 entries. Keys include a SHA-256 of the rendered page, dimensions, model and recognition version. Only detection geometry is stored, not uploaded images. Clear saved analyses removes these entries; clearing browser data or changing browser/page/rotation/model can cause another paid request. Storage failures are disclosed after analysis. Tests use synthetic responses and never call the paid API; Luna accuracy on the private sample has not been evaluated with a paid call.

Scale interpretation uses a unique strict majority whose estimates fit within a 20% total range; conflicting readings are listed for review. Ambiguous or missing scale opens a local measurement review with the selected span highlighted over the source image. Users may select a detected dimension, correct its length, or mark two endpoints. Confirming preserves the detected rooms and builds their draft with the chosen scale; cancel preserves the previous drawing. Schema-valid results are cached even when scale needs review. No provider retry is involved.

Studio openings: Add door places an existing library door; Add entrance (no door) uses the same wall-aligned opening geometry with the door model omitted. Entrance width/height/location remain editable in the studio and survive save/share/undo. Open living / hallway areas clears enclosing flags on living/dining labels and halls, preserving enclosed bedrooms/bathrooms/solariums and explicitly drawn walls. This also runs on newly imported detections; existing saved homes change only through explicit studio review. The fixtures list selects small boxes, whose free-standing drag movement no longer snaps to unrelated room boundaries.

Editing tools now live in a labeled right-hand rail. Source and scale settings collapse in the left inspector, and optional fixtures open a separate picker. Imported fixtures can be excluded without affecting doors/windows. Selected room groups expose corner handles on each component rectangle; resizing changes that rectangle only and is one undo gesture. Cut wall removes a dragged span from an inside wall, retaining its two ends, and also removes openings hosted on that span. Combine joins adjoining room groups while preserving their exact union and fixtures away from the removed boundary. Persistent wallCuts metadata reapplies cuts to generated walls on reopening; older saves omit it. Exterior walls follow the floor outline; use room resizing or entrances for exterior changes.

Current import policy: studio conversion ignores all provider fixtures (including cached results). New provider prompts request rooms and measured scale only; the right-side tools manually place fixtures and openings. Group identity includes name/type as well as model ID and separates disconnected components. Overlapped areas can be selected from an explicit point-hit list; room labels can be edited and entire rooms deleted. Grouped rooms expose Separate rectangle and Delete rectangle actions. Cross-room overlaps are flagged and prevent final 3D confirmation until corrected. These checks do not establish that the vision model traced the plan accurately.

The studio fills the viewport. File > Import PDF or image uses Luna only; View contains units, reference opacity, calibration and analysis details. Rooms & Spaces includes every room and circulation area; select an entry or canvas rectangle to edit its name, measurements or delete it. Select multiple adjoining rooms with Combine and confirm once. Magnetic movement aligns opposing nearby edges; existing divider generation emits one shared wall. Fixtures and Openings palettes accept click-to-place or captured pointer drag, using simple SVG symbols backed by existing catalog placements for 3D conversion. No paid analysis was used to validate this UI change.
